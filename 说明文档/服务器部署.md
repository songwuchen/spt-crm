## 3. 首次部署

### 3.1 上传编排与配置

在本机仓库根目录：

```powershell
$REMOTE = "songwuchen@192.168.0.39"
$REMOTE_DIR = "/home/songwuchen/spt-crm"

ssh $REMOTE "mkdir -p $REMOTE_DIR"
scp docker-compose.prod.yml $REMOTE:${REMOTE_DIR}/docker-compose.yml
scp nginx.prod.conf         $REMOTE:${REMOTE_DIR}/nginx.prod.conf
scp .env.example            $REMOTE:${REMOTE_DIR}/.env.example
```

```bash
ssh songwuchen@192.168.0.39
cd /home/songwuchen/spt-crm
sed -i 's/\r$//' docker-compose.yml nginx.prod.conf .env.example
```

> 更新 `nginx.prod.conf` 后建议：`docker compose up -d --force-recreate frontend`（不要只靠 reload，bind-mount 可能仍握旧 inode）。

### 3.2 准备 `.env`

```bash
cd /home/songwuchen/spt-crm
cp -n .env.example .env
chmod 600 .env
nano .env
```

至少设置：

```env
POSTGRES_PASSWORD=强密码
JWT_SECRET_KEY=长随机串
CORS_ORIGINS=http://192.168.0.39:39280,https://192.168.0.39:39281,https://wm.fourier.net.cn:39281,https://link.fourier.net.cn:39281,https://wm-platform.fourier.net.cn:39281
```

证书需已存在（与 ruolin-rsp 共用即可）。

### 3.3 登录 Harbor 并启动

该机容器多、核少，建议 `tmux`，并**分步** `up`（一次全开会导致 SSH 假死）：

```bash
ssh songwuchen@192.168.0.39
tmux new -s crm
cd /home/songwuchen/spt-crm

docker login wmharbor.fourier.net.cn:39011
docker compose --env-file .env pull

docker compose --env-file .env up -d db
sleep 15
docker compose --env-file .env up -d redis
sleep 5
docker compose --env-file .env up -d backend
sleep 10
docker compose --env-file .env up -d worker reminder
sleep 5
docker compose --env-file .env up -d frontend

docker compose --env-file .env ps
```

### 3.4 迁移 + seed（空库执行一次）

```bash
docker compose --env-file .env run --rm backend alembic upgrade head
docker compose --env-file .env run --rm backend python -m scripts.seed --production
docker compose --env-file .env run --rm backend python -m scripts.seed_lead_dicts
```

### 3.5 验证

```bash
curl -s http://127.0.0.1:39280/health
curl -s http://127.0.0.1:39280/ | head
docker compose --env-file .env logs --tail=50 frontend
```

## 4. 日常更新

CI 推完 Harbor 后：

```bash
ssh songwuchen@192.168.0.39
cd /home/songwuchen/spt-crm
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

仍建议在 `tmux` 里执行；卡顿则改回分步 `up`。

若本次改了 `nginx.prod.conf`，先 scp 再：

```bash
docker compose --env-file .env up -d --force-recreate frontend
```

有库结构变更时：

```bash
docker compose --env-file .env run --rm backend alembic upgrade head
```

## 5. 证书更新（同事重签 Let's Encrypt 后）

路径与 ruolin-rsp 相同，**只引用、不删除**：

- `/etc/letsencrypt/live/fourier.net.cn/fullchain.pem`
- `/etc/letsencrypt/live/fourier.net.cn/privkey.pem`

```bash
cd /home/songwuchen/spt-crm
# 证书 inode 常会变，优先 recreate，不要只 reload
docker compose --env-file .env up -d --force-recreate frontend
```

## 6. 常用命令

```bash
cd /home/songwuchen/spt-crm

docker compose --env-file .env ps
docker compose --env-file .env logs -f --tail=100 backend
docker compose --env-file .env logs -f --tail=100 frontend

# 改 .env 后重建 backend（restart 不重读 env_file）
docker compose --env-file .env up -d --force-recreate --no-deps backend

docker compose --env-file .env down    # 停服务，保留数据卷
```

## 9. 注意事项

1. **CI 只推 Harbor，不 SSH 部署**；上线靠手工 `pull && up -d`。
2. **db/redis 用官方镜像**，不要改回 Harbor 转推的 pgvector/redis（本机易假死）。
3. 证书路径与 ruolin-rsp 共用；文件不存在则 frontend/nginx 起不来。
4. `.env` 只在服务器维护；改完要对相关服务 `--force-recreate`。
5. 不要随意 `systemctl restart docker`，会停掉同机其它容器。
