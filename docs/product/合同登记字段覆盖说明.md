# 合同登记字段覆盖说明（CRM vs 简道云）

> 目标：CRM「合同」具备简道云数据中心「合同登记表」的**业务字段**，客户可在本系统完成同等登记。  
> **数据同步**：CRM **不**直连简道云拉取。由中间服务 [`crm-integration`](G:/ruolin-a/crm-integration) 从简道云拉取后，经开放平台推入。

## 第三方推送入口（已预留）

与线索/客户等写入同一套开放平台：

| 项 | 值 |
|----|----|
| 方法路径 | `POST /openapi/v1/contracts` |
| Scope | `crm.contract.write` |
| 鉴权 | `X-API-Key` 或 HMAC（`X-App-Id` / `X-Timestamp` / `X-Signature`） |
| 幂等 | 必须 `Idempotency-Key`（建议 `jdy-contract-<data_id>-<cursor>`） |
| Upsert | 租户内按 `contract_no` 存在则更新，否则创建 |

请求体核心字段见 `OpenContractCreate`（`backend/app/domains/openapi/schemas.py`）及 [开放平台API文档](./开放平台API文档.md) §5.4。

配套：先 `GET/POST /openapi/v1/customers` 解析 `customer_id`。

## 覆盖方式

| 落点 | 内容 |
|------|------|
| 原生列 | 合同号、图纸编号、对方合同号、获取方式、交货期、合同状态(新增/变动)、订货/下卡日期、金额、到期日、业务人员、部门 |
| `registration_json` | 质保、合同类型/形式、含税/出口/安装、行业地区应用、运费地址发货验收、变动原因等 |
| 子表 | 合同明细 → `key_clauses_json`；收款计划 → `payment_terms_json` |
| 附件 | 合同/协议/验收单 → 详情附件分区；OpenAPI 传 `attachments_json`（文件名即可，CRM 转 `jdy-meta:`/`jdy-oss:` 存 `registration_json._attachments`） |

## 刻意不搬（简道云表单机制，非业务主数据）

- separator / linkfield / linkquery / lookup
- 各类「辅助」「限制同一合同号…」防重列
- 停用字段（最后发货日期/发货总额等）
- 系统字段：流水号、提交人、提交/更新时间（CRM 有 created_*）

## 界面入口

- 列表：`/contracts` 标题「合同登记」，新增走全部分区字段
- 详情：分区完整展示 +「编辑登记信息」+ 分类附件上传
- 明细/收款计划：详情内编辑器（含外币、是否提醒等）

字段清单来源：`docs/product/_jdy_contract_reg_fields.json`（live schema）。
